# Security policy

Thank you for helping keep Navis Docs and its users safe.

## Reporting a vulnerability

**Please do not open a public GitHub issue for security reports.**

Instead, email **[security@navisdocs.com](mailto:security@navisdocs.com)** with:

- A short description of the issue and potential impact
- Steps to reproduce or proof of concept
- Affected versions or deployment assumptions (cloud vs self-hosted) if known

If you prefer, you may use **[hello@navisdocs.com](mailto:hello@navisdocs.com)** for routing; clearly mark the subject as `[Security]`.

We will acknowledge receipt when we can and work with you on a coordinated disclosure timeline.

## Supported versions

| Version / branch                    |  Supported  |
| ----------------------------------- | :---------: |
| `main` branch (current development) |     Yes     |
| Tagged releases older than latest   | Best effort |

For self-hosted installs, upgrading to the latest `main` or release tag before reporting can help isolate whether an issue still exists.

## Scope

Issues in this repository (`navis-docs/navis-docs`) application code and documented deployment assumptions are in scope unless otherwise noted.

Out of scope examples: third-party services you configure independently, undocumented deployments, social engineering against individuals, physical access, denial-of-service lacking clear impact beyond resource exhaustion expectations.
